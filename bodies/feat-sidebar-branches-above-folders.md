## Summary

**The problem.** With *Group branches by prefix* on (the default), the sidebar's Local and Remotes
lists sort plain branches and prefix folders together alphabetically. In any repository that uses
prefixes, the branches people look for most, `main` and `develop`, end up scattered between the
folders: `bugfix/`, `dependabot/`, then `develop`, then `feature/`, then `main`, then `release/`.
Anyone scanning for the default branch has to read past folders to find it, and the layout suggests
a relationship that does not exist: a folder sitting right above `main` reads as if its branches
fed into it. It gets worse with more prefixes, which is exactly the repositories where grouping
matters.

**What changes.**

- In the Local list and in each remote under Remotes, branches without a prefix come first and
  folders follow. Each group keeps the order it had before (alphabetical), so nothing else moves.
- The rule applies at every level of the tree: inside `feature/`, a branch named `feature/login`
  is listed above the nested `feature/payments/` folder.
- One small pure helper, `refsBeforeFolders` in `lib/prefixTree.ts`, does the ordering; the four
  places in `Sidebar.tsx` that walked a node's children now call it.
- `docs/help/branching.md` describes the order, with a new `sidebar-branches` screenshot.

**Benefits.** `main` and `develop` are always at the top of the list, in the same place in every
repository, whatever prefixes the team uses. Folders read as what they are, groups of names,
rather than as children of the branch above them.

**Limits.** Tags keep plain alphabetical order: tag folders (`release/`, `nightly/`) are usually
the point of the list, and mixing them is less confusing there. With grouping turned off the
list is flat and unchanged. A branch that is also a folder (`feat` alongside `feat/x`) has children,
so it is listed with the folders, as it was drawn before. The existing `branch-grouping.webp`
screenshot on the same page still shows the old order; I did not regenerate it because my capture
environment produces a 1x image and would replace the current 2x one. Running
`npm run screenshots branch-grouping` on a Mac refreshes it.

**Tests.** `test/pureLogic.test.ts` gains a `prefixTree` case: plain refs come before folders,
each group keeps its input order, a ref that is also a folder sorts with the folders, and an
undefined node yields an empty list.

**How to test by hand.**

1. `npm run dev` and open the `branch-grouping` playground repository
   (`examples/playground/branch-grouping`, generated by `npm run playground`).
2. The Local list shows `develop` and `main` first, then `bugfix`, `dependabot/npm_and_yarn`,
   `feature` and `release`.
3. Expand `feature`: `login` and `signup` are listed above the `payments` folder.
4. Push a few prefixed branches to a remote, or open any repository with `origin/feature/…`
   branches, and check the same order under Remotes.
5. Turn off *Group branches by prefix* in Settings: the flat list is unchanged.
